# MVP

このリポジトリのスコープ（README）を達成するシステムの、第一段階の設計・実装対象。以下の全てがMVPの内容である。

## アーキテクチャ（確定）

```
脳（AIエージェント）
──────────────────────────────────────
① セッション層   クリスタの起動・終了・画面状態の管理
② 盤面層         ドキュメント座標系＋フレームバッファ読み取り＋キャリブレーション
③ 筆層           ストローク定義 → サンプル列コンパイラ → 仮想ペンタブ → OTD → クリスタ
④ 土台           仮想モニタ / 仮想ペンタブ(vmulti) / OpenTabletDriver
```

### 入出力の原理

- **読み**: 仮想モニタのフレームバッファをキャプチャし、盤面（キャンバスの現在状態）をピクセル単位で取得する。書き込みと同一の座標系であるため、座標ズレのない盤面になる
- **書き**: 描画はOTD経由のペン入力。UIのボタン・メニュー操作も同じペンのクリックで行う。文字入力が必要な場面（キャンバスサイズの入力等）は標準のキーボード入力注入を使う
- **外部エージェント基盤への非依存**: ComputerUse等の既存の画面操作基盤は本システムの構成要素としない。読みはフレームバッファ、書きはOTD＋キーボード注入で完結する

## 設計方針

- **脳と手足の分離**: 判断・意図はすべてエージェント（脳）が担う。プログラム（手足）は機械的に忠実であることを良しとする。人間らしさ等の創作的性質はプログラムに固定せず、その都度エージェントが入力として与える
- **読みと書きの同一座標系**: フレームバッファ（読み）とペン注入（書き）が同じ座標空間に乗る
- **実績部品の組み合わせ**: 仮想ペン・仮想モニタ・タブレットドライバは実績のあるOSS（vmulti / VirtualDisplayDriver / OpenTabletDriver）を正規の使い方で利用し、自作はストロークコンパイラとセッション・盤面の管理コードに最小限限定する
- **バージョン固定運用**: 依存OSSは動作確認したバージョンに固定し、勝手な更新で壊れないようにする

状態の意味: **確定** = 使用決定済み。**設計中** = 自作予定（仕様策定中）。**実験待ち** = 実験で決める事項。

### 仮想液タブの土台（④）

液タブ＝「ペン（書く役）」＋「画面（見る役）」。以下の三つで構成する。

| 部品 | 役割 | 状態 |
|---|---|---|
| OpenTabletDriver（OTD） | ニセペンタブからの報告を公式パイプラインで処理し、Windowsのペン入力へ変換する。GUIでペン入力の流れを可視化できる | 確定（バージョン固定運用） |
| vmulti（VirtualDrivers） | ニセペンタブ装置。仮想HIDデジタイザとして「本物のペンタブが刺さった」状態を作り、OTDの入力源になる | 確定（ドライバ導入が必要） |
| VirtualDisplayDriver（VirtualDrivers） | 仮想モニタ。液タブの「画面」役。盤面の座標系を提供し、フレームバッファを読み取り可能にする | 確定（ドライバ導入が必要） |

### 自作システム（clipstudio-bridge 本体）

| 層 | 役割 | 状態 |
|---|---|---|
| ① セッション層 | クリスタの起動・終了・画面状態の判定・遷移・ダイアログ処理。筆を撃つ前に「正規のキャンバス状態」を用意する。UI操作はペンクリック（OTD経由）とキーボード注入、状態判定はフレームバッファとウィンドウ情報による | 設計中 |
| ② 盤面層 | ドキュメント座標系の定義、仮想モニタのフレームバッファ読み取り、キャリブレーション（既知点注入→実測→変換式確定） | 設計中 |
| ③ 筆層（ストロークコンパイラ） | ストローク定義（中間表現）を受け取り、位置・筆圧・時刻つきのサンプル列（毎秒約200回）に展開し、vmultiへ書き込む | 設計中 |

- 実装言語: C#（Windows内蔵コンパイラ csc でビルド可能。OTDのタブレット定義JSON・報告形式の参考実装もC#で存在するため）

## MVPスコープ（やること）

### 1. セッション（クリスタの画面状態管理）

- 仮想モニタ上でクリスタを起動する
- 新規キャンバスを作成する（固定サイズ、例: 1024×1024）
- 現在の画面状態を判定できる（起動中 / ランチャー / キャンバス画面 / ダイアログ表示中 等）
- 終了時の未保存確認ダイアログを含め、安全に終了できる

### 2. 盤面（座標系と読み取り）

- キャンバス画面を固定環境にする（ウィンドウ最大化・ズーム100%等）
- ドキュメント座標系を定義する
- キャリブレーション: 既知のドキュメント座標にテストマークを注入 → 盤面を実測 → ドキュメント座標⇔画面座標の変換式を確定する
- 仮想モニタのフレームバッファから盤面を画像として読み取る

### 3. 筆（ストロークの描画）

- ストローク定義（中間表現: 幾何＋時間＋筆圧パラメータ）を受け取り、位置・筆圧・時刻つきのサンプル列に展開する
- ニセペンタブ → OTD → クリスタの経路で実際に描画する
- ストロークの状態遷移（接触開始 → 移動 → 離脱）を保証する。異常時も必ず終端し、ペンが押しっぱなしにならない

### 4. 検証ループ

- 描画後に盤面を読み、投入したストローク定義と実測を突き合わせる
- 座標系のズレがないことを確認する。ズレがある場合は再キャリブレーションする

## 想定動作（シナリオ）

```
1. [セッション] 仮想モニタを用意し、クリスタを起動 → 新規キャンバス(1024×1024)を作成
2. [セッション] 現在の画面状態を判定 → 「キャンバス画面」であることを確認
3. [盤面] 固定環境を設定し、キャリブレーションを実行 → 変換式を確定
4. [筆] テストストローク定義（例: 直線 (200,200)→(800,700)、筆圧一定）を投入
5. [盤面] 盤面を読み取り、テストストロークの実測と期待を比較
6. 判定: 一致 → 検証成功 / ズレ → 再キャリブレーションして 4 に戻る
7. [セッション] 安全に終了
```

## スコープ外（MVPでやらないこと）

- 絵的な完成度（人間らしい線・美しい絵）: それが必要な場合はエージェントがその都度、明示的な数値（点列・筆圧分布）として入力する。プログラムに固定しない
- レイヤー操作・色調整・ブラシ細部設定の自動化: 画面状態の「判定」対象には含めるが、設定値そのものはMVPでは固定・手動とする
- 複数ドキュメント管理・高度な画面状態の網羅

## 受け入れ基準

- [ ] セッション層が「今どの画面か」を自動判定できる
- [ ] 新規キャンバス作成から終了までを自動で完走できる
- [ ] キャリブレーション後の変換で、テストストロークが期待どおりの位置・形状で描かれる
- [ ] 盤面読み取り → 描画 → 盤面読み取り の循環を少なくとも1回完結できる
- [ ] 異常時にペンが押しっぱなしにならない（状態遷移が必ず終端する）

## 実験待ち（未確定事項）

| 項目 | 内容 |
|---|---|
| クリスタのタブレットAPI設定 | クリスタがWindows Ink経由のペン（筆圧つき）を受理するか。受理しない場合の設定変更手順を確定する |
| 依存OSSのバージョン固定値 | OTD / vmulti / VirtualDisplayDriver の動作確認済みバージョンを決め、明記する |
| キャリブレーション手順 | 既知点の数・配置、実測方法、変換式の求解手順を確定する |
| キーボード注入の要否と方法 | 新規キャンバスのサイズ入力等で文字入力が必要か。必要な場合の注入方法（フォーカス管理を含む）を確定する |
| 速度依存ブラシの挙動 | サンプル列の時間間隔がクリスタの速度依存描写にどう影響するかの確認 |
