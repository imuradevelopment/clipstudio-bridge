# MVP

このリポジトリのスコープ（README）の第一段階として実現したい動作。実現手段の設計は [design.md](design.md) に記す。

## MVPの目的

「盤面（キャンバスの現在状態）を見る → 判断する → 線を描く → 再び盤面を見る」の循環を最小構成で実現し、システムが正しく機能することを証明する。

重要な前提: 「線をうまく描ける」ことだけを検証しても意味がない。クリスタを正規のキャンバス状態まで持っていく**画面状態の管理**と、**盤面の正確な読み取り**があって初めて、筆の成否の判定が成立する。以下はその三つを揃えた動作範囲である。

## 実現したい動作

### 1. 画面状態の管理

- 仮想モニタ上でクリスタが起動できる
- 新規キャンバスが作成できる（固定サイズ、例: 1024×1024）
- 現在の画面状態が判定できる（起動中 / ランチャー / キャンバス画面 / ダイアログ表示中 等）
- 終了時の未保存確認ダイアログを含め、安全に終了できる

### 2. 盤面の読み取り

- キャンバス画面が固定環境になる（ウィンドウ最大化・ズーム100%等）
- ドキュメント座標系が定義される
- キャリブレーションが行える: 既知のドキュメント座標にテストマークを注入 → 盤面を実測 → ドキュメント座標⇔画面座標の変換式が確定する
- 盤面を画像として読み取れる

### 3. ストロークの描画

- ストローク定義（幾何＋時間＋筆圧）を与えると、そのとおりの線がキャンバスに描かれる
- ストロークは必ず完結する。異常時にもペンが押しっぱなしにならない

### 4. 検証の循環

- 描画後に盤面を読み、投入したストローク定義と実測を突き合わせられる
- 座標系のズレを検出した場合、再キャリブレーションで解消できる

## 想定動作シナリオ

```
1. クリスタを起動 → 新規キャンバス(1024×1024)を作成
2. 現在の画面状態を判定 → 「キャンバス画面」であることを確認
3. 固定環境を設定し、キャリブレーションを実行 → 変換式を確定
4. テストストローク定義（例: 直線 (200,200)→(800,700)、筆圧一定）を投入
5. 盤面を読み取り、テストストロークの実測と期待を比較
6. 判定: 一致 → 検証成功 / ズレ → 再キャリブレーションして 4 に戻る
7. 安全に終了
```

## 動作範囲に含めないこと

- 絵的な完成度（人間らしい線・美しい絵）: それが必要な場合はエージェントがその都度、明示的な数値（点列・筆圧分布）として入力する。プログラムに固定しない
- レイヤー操作・色調整・ブラシ細部設定の自動化: 画面状態の「判定」対象には含めるが、設定値そのものはMVPでは固定・手動とする
- 複数ドキュメント管理・高度な画面状態の網羅
