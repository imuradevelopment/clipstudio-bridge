# 設計

MVP（[mvp.md](mvp.md)）で実現したい動作を実現するための、現時点での設計。本書が設計内容の単一の記載場所であり、更新は常にここへ行う。

## アーキテクチャ（確定）

```
脳（AIエージェント）
──────────────────────────────────────
① セッション層   クリスタの起動・終了・画面状態の管理
② 盤面層         ドキュメント座標系＋フレームバッファ読み取り＋キャリブレーション
③ 筆層           ストローク定義 → サンプル列コンパイラ → 仮想ペンタブ → OTD → クリスタ
④ 土台           仮想モニタ / 仮想ペンタブ(vmulti) / OpenTabletDriver
```

### 入出力の原理

- **読み**: 仮想モニタのフレームバッファをキャプチャし、盤面（キャンバスの現在状態）をピクセル単位で取得する。書き込みと同一の座標系であるため、座標ズレのない盤面になる
- **書き**: 描画はOTD経由のペン入力。UIのボタン・メニュー操作も同じペンのクリックで行う。文字入力が必要な場面（キャンバスサイズの入力等）は標準のキーボード入力注入を使う
- **外部エージェント基盤への非依存**: ComputerUse等の既存の画面操作基盤は本システムの構成要素としない。読みはフレームバッファ、書きはOTD＋キーボード注入で完結する

## 設計方針

- **脳と手足の分離**: 判断・意図はすべてエージェント（脳）が担う。プログラム（手足）は機械的に忠実であることを良しとする。人間らしさ等の創作的性質はプログラムに固定せず、その都度エージェントが入力として与える
- **読みと書きの同一座標系**: フレームバッファ（読み）とペン注入（書き）が同じ座標空間に乗る
- **実績部品の組み合わせ**: 仮想ペン・仮想モニタ・タブレットドライバは実績のあるOSS（vmulti / VirtualDisplayDriver / OpenTabletDriver）を正規の使い方で利用する。その他は自作する（自作範囲は「自作システム」の節のみに記載し、本書の他箇所では列挙しない）
- **バージョン固定運用**: 依存OSSは動作確認したバージョンに固定し、勝手な更新で壊れないようにする

## 部品構成

状態の意味: **確定** = 使用決定済み。**設計中** = 自作予定（仕様策定中）。

### 対象アプリ

| 部品 | 役割 | 状態 |
|---|---|---|
| CLIP STUDIO PAINT | 操作対象。ペン入力を受け付けキャンバスに描画する | 確定 |

### 土台（実績部品）

| 部品 | 役割 | 状態 |
|---|---|---|
| OpenTabletDriver（OTD） | ニセペンタブからの報告を公式パイプラインで処理し、Windowsのペン入力へ変換する。GUIでペン入力の流れを可視化できる | 確定（バージョン固定運用） |
| vmulti（VirtualDrivers） | ニセペンタブ装置。仮想HIDデジタイザとして「本物のペンタブが刺さった」状態を作り、OTDの入力源になる | 確定（ドライバ導入が必要） |
| VirtualDisplayDriver（VirtualDrivers） | 仮想モニタ。液タブの「画面」役。盤面の座標系を提供し、フレームバッファを読み取り可能にする | 確定（ドライバ導入が必要） |

### 自作システム（自作範囲はここにのみ記載する）

| 層 | 役割 | 状態 |
|---|---|---|
| ① セッション層 | クリスタの起動・終了・画面状態の判定・遷移・ダイアログ処理。筆を撃つ前に「正規のキャンバス状態」を用意する。UI操作はペンクリック（OTD経由）とキーボード注入、状態判定はフレームバッファとウィンドウ情報による | 設計中 |
| ② 盤面層 | ドキュメント座標系の定義、仮想モニタのフレームバッファ読み取り、キャリブレーション | 設計中 |
| ③ 筆層（ストロークコンパイラ） | ストローク定義（中間表現）を受け取り、位置・筆圧・時刻つきのサンプル列（毎秒約200回）に展開し、vmultiへ書き込む | 設計中 |
| ペンイベント検証器（受信ロガー） | 筆層の出力する報告列が正しい形かを、クリスタに通す前に検証する | 設計中 |

- 実装言語: C#（Windows内蔵コンパイラ csc でビルド可能。OTDのタブレット定義JSON・報告形式の参考実装もC#で存在するため）

## 実験待ち事項

設計を確定させる前に検証が必要な事項。検証結果はここに記録し、確定したものは設計書の該当箇所へ繰り込む。

| # | 事項 | 検証する内容 | 状態 |
|---|---|---|---|
| 1 | クリスタのタブレットAPI設定 | クリスタがWindows Ink経由のペン（筆圧つき）を受理するか。受理しない場合の設定変更手順を確定する | 未検証 |
| 2 | 依存OSSのバージョン固定値 | OTD / vmulti / VirtualDisplayDriver の動作確認済みバージョンを決め、設計書に明記する | 未検証 |
| 3 | キャリブレーション手順 | 既知点の数・配置、実測方法、変換式の求解手順を確定する | 未検証 |
| 4 | キーボード注入の要否と方法 | 新規キャンバスのサイズ入力等で文字入力が必要か。必要な場合の注入方法（フォーカス管理を含む）を確定する | 未検証 |
| 5 | 速度依存ブラシの挙動 | サンプル列の時間間隔がクリスタの速度依存描写にどう影響するかを確認する | 未検証 |
